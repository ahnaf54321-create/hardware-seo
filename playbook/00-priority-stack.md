# Priority stack — synthesis of both transcripts

Read this first. It combines `playbook/01` (the Promoter Blueprint) and
`playbook/02` (seven distribution strategies) into one ranked plan for the
biomedical laboratory hardware site.

**Status: provisional.** This ordering is based on what's generally true of
lab-equipment e-commerce. It will be revised once we can audit the live site —
the audit may reveal that basics like indexability or product page structure
need fixing before any of this.

## What the two transcripts agree on

Both sources make the same core argument from different angles: building is no
longer the bottleneck, distribution is. Transcript 01 frames it as "distribution
is the new moat"; transcript 02 frames it as "your job as CEO is promoter."
Both warn about the same failure mode — spending weeks on machinery that never
moves a real number.

For this project, the numbers that matter are qualified organic traffic to
commercial pages, and quote requests. Any task that can't be traced to one of
those gets deprioritized.

## Where they differ, and which applies here

Transcript 02's framework is audience-and-campaign shaped: build a following,
warm it up, run selling events. That's a good fit for creators and less good
for a company selling capital equipment to institutions, where the buyer
arrives via search with explicit intent and a budget cycle.

Transcript 01's tactics are search-and-asset shaped: build page inventory,
build tools, get cited. That maps far more directly onto this business.

So the weighting is roughly: transcript 01 supplies the tactics, transcript 02
supplies the discipline about capturing traffic instead of letting it bounce.

## The ranked plan

### Phase 0 — Audit (blocking)

Nothing below can be scoped without seeing the site. The audit answers: is the
site indexable, how are product and category pages structured, does any
structured data exist, what does the internal linking look like, and what does
Search Console already show the site ranking for.

Frequently, the highest-value fixes in this phase are unglamorous — a blocked
crawl path, missing canonical tags, faceted navigation generating duplicate
URLs, or product pages with no crawlable specification text. These beat any new
content initiative on return.

### Phase 1 — Fix the money pages

Product and category pages are where commercial-intent search lands. Priorities:
complete, crawlable specification content; `Product` structured data with
offers and specs; internal links between related equipment, compatible
consumables, and replacement parts; and unique meta titles and descriptions
built from real specs rather than templates.

### Phase 2 — Build two or three free tools

Highest-authority-per-effort work available. Start with the RCF ⇄ RPM converter
and one calculator tied to a high-margin category. Ungated, genuinely useful,
subtly branded. The goal is `.edu` and protocol-repository backlinks, which is
what makes Phase 3 rank at all.

### Phase 3 — Programmatic SEO from the catalog

Only after Phases 1 and 2. Begin with 50–100 pages on the strongest keyword
pattern (likely application → equipment, or compatibility), confirm indexation
and rankings, then scale. Real specification data, human review, no thin
templated filler.

### Phase 4 — AEO layer

Largely a byproduct of Phases 1 and 3 done well: direct answers near the top of
pages, spec tables, comparison content, FAQ schema. Add citation monitoring to
see whether LLMs start surfacing the site.

### Phase 5 — Capture and cycle

This is transcript 02's contribution. Every page from the phases above should
have a relevant capture offer, so organic traffic enters a list instead of
bouncing. Then run periodic campaigns timed to institutional budget cycles,
which is when this audience actually buys.

### Deferred

MCP server (speculative — revisit once catalog data is structured), newsletter
acquisition (revisit once LTV is known), viral artifacts (poor fit for this
market — the free tools cover the realistic sharing behavior).

## The one-line version

Fix the product pages, build calculators that earn university backlinks, scale
catalog-driven pages on that authority, and capture the traffic so it comes
back when budgets open.
